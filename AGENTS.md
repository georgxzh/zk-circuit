# Project instructions

- Read `docs/specification.md` before implementation. It defines version 1.
- Work only on the phase currently authorized by the user.
- After completing a phase, validate its acceptance criteria, update status,
  make a descriptive commit, push to `main`, and stop for user approval.
- Do not begin the following phase in the same turn without that approval.
- Never commit generated proving keys, ceremony material, build artifacts,
  witnesses, private inputs, salts used with real data, or secrets.
- Stage explicit source paths and inspect the staged diff before every commit.
- Keep mathematical correctness, implementation validation, and cryptographic
  security claims distinct. Do not describe planned proofs as completed proofs.
- Any change to version 1 semantics must update the specification, constants,
  acceptance cases, and affected proof obligations together.
